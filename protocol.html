Serial protocol

Compatible with nops / Unirom 8. Commands are 4 ASCII bytes, matched on a rolling window of the last 4 bytes received (leading noise is ignored); integers are 32-bit little-endian.

Handshake

For commands with data, the console answers OKV2 (protocol 2 offered); the PC answers UPV2 within about 150 ms to use it; then the console sends the command’s reply (usually OKAY). In protocol 2, data goes in 2 KB chunks: the receiver checks each chunk’s checksum and answers MORE (or ERR! to get it again).

PCDRV

While nops /m runs, a program’s PCDRV break sends 00 'p' + the function code (u32); the PC answers OKAY then the exchange of that function (file name, handle, length, data).

OPX1 extended link (tools/psx.py)

OpenPsxRom’s own client, next to nops (everything above is unchanged: nops never sends OPX1). The PC sends the token OPX1 at 115200 baud; the console answers OPXA and both then exchange frames, until END, a flash, an EXE start, a reset or about 3 s of silence:

A5h, cmd (u8), len (u16), payload[len], CRC32 (u32, zlib) of cmd..payload     little-endian

Each request gets exactly one answer frame with the same cmd; its payload is a status byte (0 ok, 1 damaged frame, 2 bad arguments, 3 refused, 4 failed, 5 unknown command) followed by the data. The PC sends the next request only once it has the answer. A frame damaged on the way to the console is answered with cmd FFh, status 1; one damaged on the way back fails its CRC: in both cases the PC simply sends the request again (every request can be repeated safely). A PC that lost the session can send OPX1 again inside it: the console answers OPXA and goes on.

psx.py uses them as follows:

  • flash FILE (differential flash): CRCS of the cartridge bank in 1 KB pieces, compared with the file; COPY of the bank to rombuf; only the pieces that differ are sent (LZWR when compressing makes them smaller, else WRITE); CRCS of rombuf against the file; then FLASH. An image already on the cartridge is not written again. --full sends every piece.

  • exe FILE / load FILE ADDR: the data in compressed 1 KB pieces, then EXEC for an EXE.

  • dump ADDR LEN FILE / peek ADDR [LEN]: READ in 1 KB pieces.

  • info, ping, reset.

  • tools/cheats.py reads the cheat sector with READ and writes it back with FLAREA (see Codes from a cheat database).

python tools/psx.py flash build/openrom.rom          # port from tools/comport.txt, or -p COMx
python tools/psx.py dump 0x1F000000 0x20000 bank1.bin

The link stays at 115200 baud. The PS1 cannot hit the PC’s rates exactly (33.8688 MHz / 16 / 18 = 117600 baud, 2 % fast), and with a fixed-rate adapter (CP210x) some bytes arrive wrong, mostly in data with many 0/1 transitions: the 1 KB pieces and their resend keep that cheap (about 9 KB/s). --fast asks for divisor 4 (PC at 510000, as nops /fast); it only helps with an adapter that can follow the console’s real rates (FTDI, CP2102N). Set PSX_DEBUG=1 to see every resend.

Debugging

All commands use nops v18 (/dest COMx). The link is SIO1 at 115200 bauds, 8N1.

Load and run code

From the menu:

nops /exe program.exe /dest COMx              # upload a PS-EXE and start it
nops /bin data.bin 0x80100000 /dest COMx      # upload raw data (v18: file, then address)
nops /jmp 0x80100000 /dest COMx               # jump to an address
nops /dump 0x80010000 0x1000 out.bin /dest COMx
nops /poke32 0x80100000 0x12345678 /dest COMx

Faster transfers: add /psxbaud 230400 /pcbaud 230400 to a command (/psxbaud switches the PS1, /pcbaud the PC; both are needed). The console returns to 115200 after that command, and after about 3 s without traffic. /fast (518400) needs an adapter able to do it.

While a program runs

nops /debug /dest COMx                        # install the resident debug core
nops /exe program.exe /m /dest COMx           # start it and watch its output

With the debug core (or the Serial debug in game and printf -> serial boot options for a CD):

  • printf/TTY output goes to the serial port;

  • /dump, /bin, /poke, /exe, /jmp work while the program runs;

  • /halt freezes it, /cont resumes it, /regs and /setreg read and write its registers;

  • /hookex, /hookread, /hookwrite set a hardware breakpoint (COP0), /unhook removes it;

  • a crash prints the registers on screen and on the serial port;

  • the speed options work as in the menu.

Sent to the menu, the commands that need a running program (/halt, /cont, hooks) answer ONLY, as Unirom does.

GDB

nops /gdb puts the console in debug mode and starts a GDB server on TCP port 3333. Connect a MIPS-capable GDB (gdb-multiarch):

target remote localhost:3333
break main
continue
info registers

The bridge only uses commands OpenPsxRom implements (DEBG, HALT, CONT, DUMP, SBIN, HKEX…); break instructions halt the program like a software breakpoint. A full GDB session has not been tested on hardware yet.

PCDRV

Programs can read and write files on the PC through nops /m: break with code 101h-107h (PCinit, PCcreat, PCopen, PCclose, PCread, PCwrite, PClseek); arguments in a1-a3, error in v0, result in v1. Both encodings are accepted: PSn00bSDK (break 0, 0x101) and the Sony SDK (break 0x101). The break is caught in the kernel’s exception chain, before the BIOS’s own break handling (a development-unit feature that ends in a bus error on retail consoles).

Screenshots

python tools/psxshot.py screen.png --port COMx --nops path/to/nops.exe
python tools/psxshot.py vram.png --rect 0 0 1024 512 --scale 1 --port COMx --nops ...

The SHOT command copies the picture on screen (or any VRAM rectangle) to RAM through the GPU; the script fetches it with nops /dump and writes a PNG. Works while the menu runs; no TV needed.

Memory cards

nops /mcdown 0 card.mcr /dest COMx            # read slot 1 (raw 128 KB image)
nops /mcup 0 card.mcr /dest COMx              # write it: ERASES the card

Every frame is read back after writing and rewritten if needed (a card may still be busy with the previous frame). Reading a card takes several seconds before the transfer starts.

Emulator

tools/run_duck.ps1 boots build/openrom.rom in a DuckStation copy configured for Xplorer cartridge emulation and prints the TTY log; tools/shot.ps1 captures its window. The SHOT compile option (make DEFS=-DSHOT=n) opens a screen directly, for screenshots without a pad.
